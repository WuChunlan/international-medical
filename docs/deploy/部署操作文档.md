## 1. 架构总览

本项目由 4 个可部署单元组成：

| 单元 | 技术栈 | 端口(本地) | 访问对象 | 部署形态 |
|------|--------|-----------|----------|----------|
| backend | Spring Boot 3.2.5 / Java 17 + MyBatis-Plus + JWT | 8080 | 内部（被前端调用） | JAR 常驻进程 |
| frontend-site-a | React 19 + Vite（宣传站） | 3000 | **海外用户** | 静态文件 → Nginx |
| frontend-admin | React 19 + Vite（后台） | 3002 | **国内运营** | 静态文件 → Nginx |
| MySQL 8 + Redis | 数据库 / 缓存(验证码) | 3306 / 6379 | 仅后端访问 | 同机自建（本机内网） |

> `frontend-site-b`（用户服务网站）本次不部署，仅上线 site-a 与 admin。

**依赖关系（本项目最终形态：同一台香港服务器，域名区分）：**

```
海外用户 ──HTTPS──> [CDN 边缘节点] ──回源──┐
                                          ▼
                          香港服务器 1.2.3.4 : Nginx （同一台机器）
国内运营 ──HTTPS────────────────────────> │
                                          ├── www.example.com   → site-a 静态站 + /api /media 反代 8080
                                          └── admin.example.com → admin 静态站 + /api /media 反代 8080（限国内访问）
                                                        │
                                          后端 8080 ──> MySQL 3306 / Redis 6379（本机内网，不对外）
                                          后端上传文件 ──> 本地磁盘 upload_base_path，经 /media/** 对外提供
```

**必须知道的项目现状**（来自代码，部署时要改）：

- `backend/src/main/resources/application.yml`：MySQL 密码 `123456`、JWT secret 硬编码、mail 为占位符、CORS 只允许 `localhost:3000/3001/3002`。
- 数据库表 `site_config` 中 `upload_base_path` = `/Users/wuchunlan/Desktop/医疗平台媒体资源`（Mac 路径，**上线必须改成 Linux 路径**），`upload_base_url` = `http://localhost:8080/media`（**必须改成正式域名**）。
- 上传单文件上限 **2GB**（`max-file-size: 2048MB`），Nginx 需放开 `client_max_body_size`。
- 文件存本地磁盘，通过 Spring 的 `/media/**` 资源映射对外提供（见 `WebMvcConfig.java`）。

## 2. 核心决策：为什么这样选服务器

> **本项目已定方案（不再是"推荐"）：整套部署在一台香港服务器，通过不同域名区分 site-a 与 admin，免 ICP 备案。第一优先级是 site-a 的海外获客。**
> 你已确定采购的机器：阿里云 **中国香港** 地域，**4 vCPU / 16 GiB / 80 GiB 系统盘 / 200 Mbps 峰值 BGP 带宽 / Alibaba Cloud Linux 3**（系统镜像，**不要选翼龙面板等应用镜像**）。硬件完全够用。

### 为什么是香港单机（而不是大陆）

第一优先级是 **site-a 海外获客**。围绕这个目标：

- **海外用户访问**：香港国际出口质量好，海外用户访问延迟远低于大陆服务器（大陆服务器海外访问常 200ms+ 且丢包）。这是选香港的核心原因。
- **免 ICP 备案**：香港/海外服务器不需要备案，省掉国内 7–20 天备案时间，域名解析完即可上线。
- **国内运营访问 admin**：香港对国内延迟约 50–80ms，低频后台完全可接受。
- **单机运维最省心**：一台 4C16G 同时跑 Nginx + 后端 JAR + MySQL + Redis，只维护一台机器，性价比最高。

各方案对比（供你确认判断，本项目走 A）：

| 方案 | 海外获客 | 备案 | 说明 |
|------|---------|------|------|
| **A. 整套放香港（本项目采用）** | ✅ 快 | ✅ 免备案 | 单机承载全部，运维最简单 |
| B. 全放大陆 | ❌ 慢，需 CDN 补偿 | ❌ 必须备案 | 数据合规最强，但与"海外第一"矛盾 |
| C. site-a 海外 + 后端国内 | 一般 | 需备案 | 跨境调后端，双运维，不推荐 |

### 关于翼龙面板（Pterodactyl）

采购页的"应用镜像"里如果出现**翼龙面板**，**不要选**——它是管理游戏服务器（如 Minecraft）的面板，与本医疗平台无关，只会增加攻击面。**选"系统镜像 = Alibaba Cloud Linux 3"即可**，本文档命令与之兼容。

### 一台还是多台

初期数据量和并发不大，**这台 4C16G 单机**即可同时跑 Nginx + 后端 JAR + MySQL + Redis。
当并发上来或需要高可用时，再按此顺序拆分：① MySQL 迁移到云数据库 RDS → ② Redis 迁到云缓存 → ③ 后端多实例 + 负载均衡 → ④ 静态与媒体前置 CDN。本文档按"单机起步、预留扩展"设计。

### 海外获客的加速方案（第一优先级，重点）

香港服务器已经比大陆快，但要把"海外获客"做到位，建议叠加以下手段（按投入产出排序，可分阶段上）：

1. **香港节点本身**（已选）：覆盖东南亚、中国大陆、港澳台效果最好，欧美尚可。
2. **CDN 加速静态站与媒体**（强烈建议）：把 site-a 的静态文件（js/css/图片）和 `/media` 媒体走 CDN 全球边缘节点。海外用户就近取静态资源，首屏快很多。阿里云 CDN / Cloudflare 均可，Cloudflare 有免费套餐、全球节点多，适合海外获客起步。
3. **若欧美/中东为主要市场**：单靠香港延迟偏高，可考虑"全站 Cloudflare 代理"或后续把 site-a 静态资源部署到更靠近目标市场的对象存储 + CDN；后端仍留香港。
4. **图片/视频优化**：宣传站体积大，务必开启 CDN 缓存、图片压缩、`Cache-Control` 长缓存（第 9 节 Nginx 已配）。

> 具体 CDN 接入步骤见第 4.6 节。起步阶段"香港服务器 + Cloudflare 免费 CDN"即可显著改善海外体验，成本低。

### 3.2 系统镜像差异提醒（Alibaba Cloud Linux 3）

本文档命令示例以 Ubuntu 为主，但你用的是 **Alibaba Cloud Linux 3**（RHEL 系），包管理器是 `dnf/yum` 而非 `apt`。对照如下，正文遇到 `apt` 时按此替换即可：

| Ubuntu 命令 | Alibaba Cloud Linux 3 对应 |
|-------------|---------------------------|
| `apt update && apt upgrade -y` | `dnf update -y` |
| `apt install -y openjdk-17-jdk` | `dnf install -y java-17-openjdk java-17-openjdk-devel` |
| `apt install -y nginx` | `dnf install -y nginx` |
| `apt install -y mysql-server` | 见 6.1（RHEL 系用 MySQL 官方 yum 源） |
| `apt install -y redis-server` | `dnf install -y redis` |
| 防火墙 `ufw` | 用 `firewalld`（`firewall-cmd`）或直接用阿里云**安全组** |
| Nginx 站点目录 `sites-available/enabled` | RHEL 系默认用 `/etc/nginx/conf.d/*.conf` |

> **阿里云安全组**：除了系统防火墙，务必在阿里云控制台的"安全组"里也只放行 22/80/443，**不要放行 8080/3306/6379**。安全组是第一道防线。

## 4. 域名申请与解析（阿里云）

> 域名在**阿里云**购买与解析。本节给出从买域名 → 实名 → DNS 解析 → （可选）CDN 的完整操作步骤。

### 4.1 域名规划

假设你的主域名为 `example.com`，按如下分配子域名：

| 用途 | 域名 | 指向 |
|------|------|------|
| 宣传站 site-a（海外） | `www.example.com` 和 `example.com` | 香港服务器公网 IP（建议经 CDN） |
| 后台 admin（国内运营） | `admin.example.com` | 同一台香港服务器公网 IP（直连，不走 CDN） |
| 后端 API | **不单独暴露**，走 `www` / `admin` 的 `/api` 反代 | — |

> 后端不建议单独开子域名对外，统一通过 Nginx 的 `/api`、`/media` 路径反代到 8080，减少跨域和攻击面。

### 4.2 在阿里云购买域名（详细步骤）

> 全程在阿里云中国站控制台完成。下面以主域名 `example.com` 为例，实际操作时换成你想要的域名。

**第 1 步：选域名后缀**

- `.com`：最通用、海外用户认可度最高，**医疗/企业站首选**。
- `.net` / `.co`：`.com` 被占用时的备选。
- `.cn` / `.com.cn`：面向国内，但 `.cn` 解析到境外服务器时对实名要求更严，海外获客不推荐。
- 不建议用冷门后缀（如 `.xyz`、`.top`），海外用户信任度低、易被邮件系统判垃圾。

**第 2 步：搜索并加入清单**

1. 登录阿里云 → 顶部搜索进入 [万网域名 / 域名注册](https://wanwang.aliyun.com/domain/)（阿里云域名业务即原万网）。
2. 在搜索框输入你想要的名字（如 `international-medical`），查看 `.com` 是否可注册。
3. 可注册的加入"清单"，点结算。

**第 3 步：填写域名信息模板（关键）**

阿里云要求域名绑定一个"信息模板"（即注册人信息），并且**必须实名认证**：

1. 首次购买会提示"创建信息模板"。选择注册人类型：
   - **企业**：填公司名称、营业执照证件号，上传营业执照。
   - **个人**：填真实姓名、身份证号，上传身份证。
2. 提交后阿里云做实名审核（一般 **几小时~1 个工作日**）。
3. 建议注册人信息用企业主体（医疗平台更正规，也利于后续对公事务）。

> ⚠️ **实名认证是硬性要求**（工信部规定，与是否备案无关）。域名实名通过后才能正常解析使用。这一步和"ICP 备案"是两回事，不要混淆——**实名要做，备案（香港服务器）不用做**。

**第 4 步：支付并开启自动续费**

1. 选择购买年限（建议 **一次买 2–3 年**，避免忘记续费导致域名被抢注，医疗品牌域名尤其重要）。
2. 支付完成后，在 [域名控制台](https://dc.console.aliyun.com/) 可看到你的域名。
3. **强烈建议开启"自动续费"**，域名过期被删除后果严重。

**第 5 步：开启域名安全设置（数据安全相关）**

在域名控制台对该域名：

- 开启 **域名锁定（Transfer Lock / 禁止转移）**，防止被恶意转出。
- 开启 **信息修改保护**。
- 绑定阿里云账号的**多因素认证（MFA）**，防止账号被盗导致域名丢失。

### 4.3 是否需要备案？（结论：不需要）

**本项目服务器在香港 → 不需要 ICP 备案** ✅。域名实名通过后，直接做解析（4.4）即可对外访问，省掉国内 7–20 天备案等待。

| 事项 | 是否需要 | 说明 |
|------|---------|------|
| 域名**实名认证** | ✅ 需要 | 工信部规定，所有域名都要，几小时~1 天，见 4.2 第 3 步 |
| **ICP 备案** | ❌ 不需要 | 仅大陆服务器才需要，香港免备案 |

### 4.4 在阿里云配置 DNS 解析（详细步骤）

阿里云买的域名，默认就用阿里云的 DNS（云解析 DNS），无需改 NS。以香港服务器公网 IP `1.2.3.4` 为例：

**第 1 步：进入解析设置**

1. 登录 [阿里云域名控制台](https://dc.console.aliyun.com/)。
2. 找到 `example.com` → 点右侧 **"解析"**（或"解析设置"）进入云解析 DNS 页面。

**第 2 步：添加解析记录**

点"添加记录"，依次添加下面 3 条：

| 记录类型 | 主机记录 | 解析请求来源(线路) | 记录值 | TTL | 用途 |
|---------|---------|-----------------|--------|-----|------|
| A | `www` | 默认 | `1.2.3.4` | 10 分钟 | 宣传站 site-a |
| A | `@` | 默认 | `1.2.3.4` | 10 分钟 | 裸域 example.com（跳转到 www） |
| A | `admin` | 默认 | `1.2.3.4` | 10 分钟 | 后台 admin |

> - "主机记录"就是子域名前缀：`www` 对应 `www.example.com`，`@` 对应裸域 `example.com`，`admin` 对应 `admin.example.com`。
> - "记录值"填你香港服务器的**公网 IP**（在阿里云轻量应用服务器控制台可查到）。
> - TTL 先设短（10 分钟），方便改错时快速生效；上线稳定后可调大。

**第 3 步：验证解析生效**

解析通常几分钟内生效。在本地终端验证：

```bash
ping www.example.com          # 看是否返回 1.2.3.4
dig www.example.com +short    # 应输出 1.2.3.4
dig admin.example.com +short  # 应输出 1.2.3.4
```

若还没生效，等待几分钟或换 `dig @223.5.5.5 www.example.com`（阿里云公共 DNS）再查。

**第 4 步：关于 CDN 的解析（如接入，见 4.6）**

- 若给 site-a 接阿里云 CDN：`www` 那条记录会从 `A → IP` 改成 **`CNAME → CDN 分配的加速域名`**（阿里云 CDN 控制台会给你一个 `xxx.w.kunlunxx.com` 之类的 CNAME）。
- `admin` 始终保持 `A → 服务器 IP` 直连，**后台不接 CDN**。
- 若用 Cloudflare，则要改 NS（见 4.6 选项一），此时 DNS 记录在 Cloudflare 面板加，而不是阿里云。

### 4.5 域名与站点的对应关系（本项目最终形态）

同一台服务器、同一个公网 IP，Nginx 靠 `server_name` 区分不同域名：

```
www.example.com / example.com  ─┐
                                 ├─> 香港服务器 1.2.3.4 : Nginx
admin.example.com  ──────────────┘        ├── www*  → site-a 静态站 + /api /media 反代后端
                                           └── admin* → admin 静态站 + /api /media 反代后端
```

- **site-a** 面向海外，走 `www` / 裸域，建议叠加 CDN。
- **admin** 只给国内运营，走 `admin` 子域，**不上 CDN、加 IP 白名单/地域限制**（见 9.3），减少暴露面。

### 4.6 CDN 加速 site-a（海外获客关键，可上线后再接）

> CDN 不是上线必需，但对海外获客体验帮助很大。**建议先按 4.4 用普通 A 记录直连把站点跑通，再回头接 CDN。**

**怎么选：**

| | Cloudflare | 阿里云 CDN / DCDN |
|---|---|---|
| 海外节点 | 全球节点多，欧美/中东覆盖好 | 海外有节点，但偏亚太 |
| 费用 | **有免费套餐** | 按流量计费 |
| 附带能力 | 免费 DDoS + WAF | 需另配安全产品 |
| DNS 影响 | **要把 NS 改到 Cloudflare** | 域名留在阿里云，只改 www 为 CNAME |
| 建议 | **海外获客首选**（尤其欧美市场） | 已重度用阿里云、且以亚太为主时用 |

**选项一：Cloudflare（海外获客推荐，免费起步）**

1. 注册 Cloudflare，Add a site 填 `example.com`，选 Free 套餐。
2. Cloudflare 会给你**两个 NS 地址**。回阿里云域名控制台 → 该域名 → **"DNS 修改 / 修改 DNS 服务器"**，把默认的阿里云 NS 改成 Cloudflare 给的两个。（NS 变更全球生效需几十分钟到几小时）
3. 在 Cloudflare DNS 面板添加记录：
   - `www` → A → `1.2.3.4`，**代理开启（橙色云朵）** ← 走 CDN
   - `@`（裸域）→ A → `1.2.3.4`，代理开启
   - `admin` → A → `1.2.3.4`，**代理关闭（灰色云朵）** ← 后台直连，不走 CDN
4. SSL/TLS 模式选 **Full (strict)**（需服务器已装 Let's Encrypt 证书，见 9.2）。
5. Caching → 对静态资源（js/css/图片）长缓存；新增 Cache Rule 对 `/api/*` 设 **Bypass cache**（接口绝不缓存）。

> 注意：改用 Cloudflare 后，DNS 记录就在 Cloudflare 加，**不再用阿里云云解析**（4.4 的记录相当于迁到 Cloudflare 重加一遍）。

**选项二：阿里云 CDN（域名留在阿里云，配置更简单）**

1. 阿里云控制台开通 **CDN**，添加加速域名 `www.example.com`。
2. 业务类型选"图片小文件 / 全站加速(DCDN)"；**源站**类型选 IP，填 `1.2.3.4`，回源端口 **443**（HTTPS 回源）。
3. 阿里云分配一个 **CNAME 地址**（形如 `www.example.com.w.kunlunxx.com`）。
4. 回 4.4 的云解析 DNS：把 `www` 那条记录从 `A → 1.2.3.4` 改成 **`CNAME → 阿里云给的 CDN 地址`**。
5. 在 CDN 控制台配缓存规则：静态资源长缓存；`/api/` 路径设"不缓存"。
6. 在 CDN 域名管理里配 HTTPS 证书（可上传或用阿里云免费证书）。
7. `admin` 保持 `A → 服务器 IP` 直连，不接 CDN。

> **两个选项都要注意**：`/api/` 和涉及鉴权的 `/media` 不要被 CDN 缓存；纯静态和公开图片可缓存。第 9 节 Nginx 已对静态资源设了 `Cache-Control`，与 CDN 配合更好。

## 7. 后端部署（Spring Boot）

### 7.1 用生产配置覆盖，不改源码里的默认值

不要把密码写死在 `application.yml` 提交到 git。做法：打包时保留默认 `application.yml`，在服务器上用**外置配置文件 + 环境变量**覆盖。

先把 `application.yml` 里以下项改造为可被环境变量覆盖（若源码未支持占位符，可直接用外置 `application-prod.yml` 覆盖同名 key）：

在服务器新建 `/opt/intlmed/config/application-prod.yml`：

```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/international_medical?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: intlmed
    password: 换成第6步设置的强密码
  data:
    redis:
      host: localhost
      port: 6379
      password: 换成Redis密码
  mail:
    host: smtp.你的邮件服务商.com
    port: 587
    username: noreply@example.com
    password: 换成真实邮箱授权码

jwt:
  secret: 换成一串足够长的随机字符串_至少256位_不要用默认值
  expiration: 86400000
  admin-expiration: 28800000

app:
  cors:
    allowed-origins:
      - https://www.example.com
      - https://example.com
      - https://admin.example.com
  mail:
    from: noreply@example.com
    verify-code-ttl: 600
    verify-code-resend-interval: 60
```

> **注意 CORS**：源码默认只允许 `localhost`，上线后必须改成正式域名（如上），否则前端调用后端会被浏览器拦截。

## 9. Nginx 配置（反向代理 + HTTPS）

### 9.1 站点配置

新建 `/etc/nginx/sites-available/intlmed.conf`：

```nginx
# ---------- 宣传站 site-a：www.example.com + example.com ----------
server {
    listen 80;
    server_name www.example.com example.com;

    root /var/www/site-a;
    index index.html;

    # 上传大文件（后端允许 2GB），放开限制
    client_max_body_size 2100m;

    # SPA 路由：找不到文件回退 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反代
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    # 媒体文件反代（后端 /media/** 资源映射）
    location /media/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}

# ---------- 后台 admin：admin.example.com ----------
server {
    listen 80;
    server_name admin.example.com;

    root /var/www/admin;
    index index.html;
    client_max_body_size 2100m;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    location /media/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用并测试：

```bash
sudo ln -s /etc/nginx/sites-available/intlmed.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default   # 移除默认站点
sudo nginx -t                                  # 语法检查
sudo systemctl reload nginx
```

### 9.2 配置 HTTPS（Let's Encrypt 免费证书）

```bash
sudo apt install -y certbot python3-certbot-nginx

sudo certbot --nginx \
  -d example.com -d www.example.com -d admin.example.com

# certbot 会自动改写上面的 server 块，加上 443 监听和证书路径，
# 并自动把 80 重定向到 443。
```

证书自动续期（certbot 已装定时任务，可手动验证）：

```bash
sudo certbot renew --dry-run
```

> HTTPS 生效后，第 6.3 步的 `upload_base_url` 和第 7.1 的 CORS、第 8.1 的 `.env.production` 都必须是 `https://`，保持一致，否则会有混合内容(mixed content)拦截。

### 9.3 【可选】限制 admin 只允许国内访问

需求里 admin 只需国内访问。可在 `admin.example.com` 的 server 块加 IP 白名单，或用云厂商安全组/WAF 做地域限制。最简单的运营 IP 白名单示例：

```nginx
# 放在 admin server 块的 location / 里
location / {
    allow 你的办公室出口IP;      # 允许的国内 IP
    allow 另一个允许的IP;
    deny all;                    # 其余全部拒绝
    try_files $uri $uri/ /index.html;
}
```

> 若运营 IP 不固定，改用云厂商 WAF 的"地域访问控制"仅放行中国大陆，或加一层登录网关。

## 10. 数据安全加固（重点章节）

医疗平台涉及用户个人信息与咨询数据，数据安全是硬要求。下面按"网络层 → 主机层 → 应用层 → 数据层 → 备份与审计"分层加固，请逐项落实。

### 10.1 加固总览清单

| 层 | 项 | 操作 |
|----|----|----|
| 网络 | 阿里云安全组 | 只放行 22/80/443；**8080/3306/6379 绝不对公网开放** |
| 网络 | HTTPS | 全站强制 HTTPS，证书自动续期，`http` 跳 `https` |
| 网络 | admin 访问控制 | IP 白名单 / WAF 仅放行国内（见 9.3） |
| 网络 | DDoS/WAF | 用 Cloudflare 或阿里云 WAF 挡攻击与恶意爬虫 |
| 主机 | SSH | 密钥登录，关闭密码登录，禁用 root 直登，改非默认端口(可选) |
| 主机 | 最小权限 | 应用用 `deploy` 用户跑，非 root |
| 主机 | 系统更新 | 定期 `dnf update` 打安全补丁 |
| 应用 | JWT secret | 换随机强 secret，**不用源码默认值** |
| 应用 | 密码/密钥 | 全部外置配置，`chmod 600`，不提交 git |
| 应用 | CORS | 只允许正式域名，不留 `localhost` |
| 应用 | 默认账号 | **首次上线立即改掉 `admin/12345`、`Admin@123456` 等默认密码** |
| 数据 | 数据库账号 | 专用账号 `intlmed`，非 root，强密码，只监听 127.0.0.1 |
| 数据 | Redis | 设 `requirepass`，只监听本机 |
| 数据 | 磁盘加密 | 数据盘开启云盘加密（阿里云控制台） |
| 数据 | 上传目录 | 权限最小化；后续可迁对象存储 OSS |
| 备份 | 数据库 | 每日 `mysqldump` 定时备份 + 异地/OSS 存储 |
| 备份 | 媒体 | 定期备份上传目录到 OSS |
| 审计 | 日志 | 保留后端与 Nginx 访问日志，定期查异常 |

### 10.2 网络层：只暴露必要端口

阿里云控制台 → 轻量应用服务器 → 防火墙/安全组，**仅保留**：

```
22   (SSH，建议进一步限制来源 IP)
80   (HTTP，仅用于跳转 HTTPS)
443  (HTTPS)
```

**务必确认 8080、3306、6379 没有对公网开放**——后端、MySQL、Redis 只在服务器本机内部通信。系统内也用 firewalld 双保险：

```bash
systemctl enable --now firewalld
firewall-cmd --permanent --add-service=ssh
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
```

### 10.3 主机层：SSH 加固

```bash
# 编辑 /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no      # 先确保已配置密钥登录，否则会锁死自己
PubkeyAuthentication yes

systemctl restart sshd
```

> 配置密钥登录前，先在本地 `ssh-keygen` 生成密钥，用 `ssh-copy-id deploy@服务器IP` 上传公钥并验证能免密登录，**再**关闭密码登录。

### 10.4 应用层：清除默认凭据（上线必做）

项目 README 里有默认账号 `admin / 12345`、`Admin@123456`，以及硬编码的 JWT secret。**这些上线前必须全部替换**：

- 登录后台后立即修改管理员密码为强密码。
- `application-prod.yml` 的 `jwt.secret` 换成随机长字符串：
  ```bash
  openssl rand -base64 48   # 生成一串随机 secret 填进去
  ```
- 外置配置文件权限收紧：
  ```bash
  chmod 600 /opt/intlmed/config/application-prod.yml
  chown deploy:deploy /opt/intlmed/config/application-prod.yml
  ```

### 10.5 数据层：数据库与磁盘加密

- MySQL 只监听 `127.0.0.1`（默认），专用账号 `intlmed` 非 root（见 6.1）。
- Redis 设 `requirepass` 且只监听本机（见 6.4）。
- **云盘加密**：在阿里云控制台对系统盘/数据盘开启加密（存储层 AES-256），丢盘也无法读取数据。
- 传输层：全站 HTTPS，浏览器到服务器全程加密。

### 10.6 备份策略（防勒索、防误删、防丢盘）

**MySQL 每日备份**（写入 crontab）：

```bash
# crontab -e
0 3 * * * mysqldump -u intlmed -p'密码' --single-transaction international_medical | gzip > /data/backup/db_$(date +\%F).sql.gz
# 只保留最近 14 天
5 3 * * * find /data/backup -name 'db_*.sql.gz' -mtime +14 -delete
```

**媒体目录备份 + 异地存储**：仅有本机备份不够（丢盘/勒索会一起没）。建议把 `/data/backup` 和上传目录**同步到阿里云 OSS**（用 `ossutil` 定时上传），实现异地容灾：

```bash
# 安装 ossutil 后，定时同步（示例）
```

### 10.7 审计与监控

- 保留 Nginx 访问日志（`/var/log/nginx/`）和后端日志（`journalctl -u intlmed-backend`），定期查异常登录、异常上传。

### 10.8 关于数据合规的说明

你的第一优先级是海外获客，数据放在香港。补充两点合规提示：

- 香港属中国，但与大陆是不同法域；如果你的用户**包含欧盟居民**，需关注 GDPR（隐私政策、Cookie 同意、数据主体权利）。
- 如果后续业务重心转向**中国大陆用户的个人健康信息**，从《个人信息保护法》《数据安全法》角度，境内存储更稳妥——届时可把数据库迁回大陆 RDS，站点静态资源仍可放香港/CDN。当前海外优先的定位下，香港方案没有问题。

## 12. 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 前端调接口报 CORS 错误 | 后端 `allowed-origins` 还是 localhost | 改 `application-prod.yml` 的 CORS 为正式域名并重启后端 |
| 上传的图片打不开 / 404 | `upload_base_path` / `upload_base_url` 还是 Mac 路径或 localhost | 按 6.3 更新 `site_config` 表 |
| 上传大文件报 413 | Nginx `client_max_body_size` 太小 | 设为 `2100m` 并 reload |
| 刷新前端子路由 404 | 缺 SPA 回退 | Nginx `try_files $uri /index.html` |
| 后端连不上数据库 | 密码/账号/URL 错 | 核对 `application-prod.yml`，`journalctl -u intlmed-backend` 看报错 |
| 验证码功能异常 | Redis 没连上或没设密码 | 检查 Redis 密码与后端配置一致 |
| 混合内容被拦截 | 前端 https 页面里出现 http 资源 | 统一所有 URL 为 https（CORS/upload_base_url/.env） |
| 海外访问慢 | 带宽不足或未上 CDN | 提升带宽 / 前置 CDN 加速静态与媒体 |
