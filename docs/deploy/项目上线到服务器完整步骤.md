# 国际医疗平台 — 项目上线到服务器完整步骤

> 本文档由现有《上线操作手册.md》和《部署操作文档.md》重新整合生成，目标是让执行人员从服务器采购、域名解析、环境安装、数据库初始化、后端部署、前端部署、HTTPS、安全加固到上线验证，全流程按顺序操作即可。
>
> 适用系统：Alibaba Cloud Linux 3（RHEL 系，使用 `dnf`）。
>
> 部署形态：一台阿里云香港服务器同时运行 Nginx + Spring Boot 后端 JAR + MySQL + Redis；`www.scohospital.com` 访问宣传站 site-a，`admin.scohospital.com` 访问后台 admin。

## 0. 上线结论与关键约定

### 0.1 本次上线范围

| 模块 | 路径 | 技术栈 | 上线形态 | 对外访问 |
|---|---|---|---|---|

## 2. 阶段 1：采购服务器与域名

### 2.1 购买阿里云香港服务器

在阿里云控制台购买服务器：

- 地域选择：中国香港。
- 配置选择：4 vCPU / 16 GiB / 80 GiB 系统盘 / 200 Mbps BGP。
- 系统镜像选择：Alibaba Cloud Linux 3。
- 不要选择翼龙面板等应用镜像。
- 设置 root 密码或绑定 SSH 密钥。
- 记下公网 IP，后文以 `1.2.3.4` 表示。

### 2.2 配置阿里云安全组

阿里云安全组只放行：

| 端口 | 用途 |
|---|---|
| 22 | SSH，建议后续限制来源 IP |
| 80 | HTTP，用于证书申请和跳转 HTTPS |
| 443 | HTTPS |

必须确认不要放行：

- `8080`：后端只允许 Nginx 本机反代。
- `3306`：MySQL 只允许本机访问。
- `6379`：Redis 只允许本机访问。

### 2.3 购买域名并实名

在阿里云万网购买域名，建议：

- `.com` 优先。
- 使用企业主体信息模板更正式。
- 提交域名实名认证。
- 开启自动续费。
- 开启域名锁定、信息修改保护。
- 阿里云账号开启 MFA。

说明：香港服务器不需要 ICP 备案，但域名实名认证仍然必须完成。实名通过后才能正常解析。

dig scohospital.com +short

## 5. 阶段 4：安装 MySQL 8 与 Redis

### 5.1 安装 MySQL 8

> 重要：Alibaba Cloud Linux 3 基于 RHEL 8 ABI（glibc 2.32），必须使用 **el8** 版本的 MySQL 源。不要用 el9 源，否则会报 `nothing provides libc.so.6(GLIBC_2.34)` 依赖错误。

```bash
dnf install -y https://dev.mysql.com/get/mysql84-community-release-el8-1.noarch.rpm
dnf install -y mysql-community-server
systemctl enable --now mysqld
systemctl status mysqld
```

如果安装报 GPG 校验错误，先导入 MySQL 签名密钥再重试：

```bash
rpm --import https://repo.mysql.com/RPM-GPG-KEY-mysql-2023
dnf install -y mysql-community-server
```

如果之前误装了 el9 源，先卸载再按上面重装：

```bash
dnf remove -y mysql84-community-release
```

查看临时 root 密码：

```bash
grep 'temporary password' /var/log/mysqld.log
```

执行安全初始化：

```bash
mysql_secure_installation
```

按提示使用临时密码登录，并设置新的 MySQL root 强密码。

### 5.2 创建业务数据库与专用账号

进入 MySQL：

```bash
mysql -u root -p
```

执行：

```sql
CREATE DATABASE international_medical
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'intlmed'@'localhost' IDENTIFIED BY '换强密码_DB';
GRANT ALL PRIVILEGES ON international_medical.* TO 'intlmed'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

验证业务账号可登录：

```bash
mysql -u intlmed -p international_medical -e "SELECT DATABASE();"
```

期望输出包含：

```text
international_medical
```

### 5.3 安装 Redis

```bash
dnf install -y redis
systemctl enable --now redis
systemctl status redis
```

编辑 Redis 配置：

> 注意：Alibaba Cloud Linux 3 上 Redis 配置文件通常在 `/etc/redis.conf`（没有 `redis/` 子目录）。若 `vi /etc/redis/redis.conf` 打开是空文件，说明路径不对，先执行 `rpm -ql redis | grep -E '\.conf$'` 找到真实路径再编辑。

```bash
# 先确认真实配置文件路径
rpm -ql redis | grep -E '\.conf$'
# 常见为 /etc/redis.conf
vi /etc/redis.conf
```

在文件中确认或修改以下两项（`bind` 在 NETWORK 段，`requirepass` 在 SECURITY 段，默认被注释）：

```conf
bind 127.0.0.1 ::1
requirepass 换强密码_REDIS
```

> 配置文件很长、两项分散在不同段落，手动查找容易漏。更省事的做法是不改原行，直接把这两行追加到文件末尾（Redis 以最后出现的配置为准）：
>
> ```bash
> sudo tee -a /etc/redis.conf > /dev/null <<'EOF'
>
> # ==== 上线安全配置（追加，末尾生效） ====
> bind 127.0.0.1 ::1
> requirepass 换强密码_REDIS
> EOF
> ```

重启 Redis：

```bash
systemctl restart redis
systemctl status redis
```

验证：

```bash
redis-cli -a '换强密码_REDIS' ping
```

期望输出：

```text
PONG
```

### 6.3 检查上传配置

上传图片和视频依赖 `site_config` 表中的配置。先查看当前值：

```bash

"SELECT config_key,value_zh FROM site_config WHERE config_key LIKE 'upload_%';"
```

常见初始问题：

| config_key | 初始值问题 | 上线必须改为 |
|---|---|---|
| `upload_base_path` | 可能是 Mac 本地路径 | `/data/uploads/media` |
| `upload_base_url` | 可能是 `http://localhost:8080/media` | `https://www.scohospital.com/media` |
| `upload_max_size_mb` | 可能是 `50` 或 `50000` | `5000`（5GB，与 Spring、Nginx 对齐） |

### 6.4 修正上传配置

进入 MySQL：

```bash
mysql -u intlmed -p international_medical
```

执行：

```sql
UPDATE site_config SET value_zh='/data/uploads/media', value_en='/data/uploads/media'
  WHERE config_key='upload_base_path';

UPDATE site_config SET value_zh='https://www.scohospital.com/media', value_en='https://www.scohospital.com/media'
  WHERE config_key='upload_base_url';

UPDATE site_config SET value_zh='5000', value_en='5000'
  WHERE config_key='upload_max_size_mb';

-- 如需支持 mkv，可打开下面语句：
-- UPDATE site_config SET value_zh='mp4,mov,avi,webm,mkv', value_en='mp4,mov,avi,webm,mkv'
--   WHERE config_key='upload_allowed_video_types';

EXIT;
```

### 6.5 创建上传目录并授权

```bash
mkdir -p /data/uploads/media
chown -R deploy:deploy /data/uploads
chmod -R 755 /data/uploads
```

重要说明：

上传单文件上限为 5GB，三层必须一起对齐，任何一层小了都会先被拦截：

| 层 | 位置 | 设为 | 说明 |
|---|---|---|---|
| 应用层 | 数据库 `upload_max_size_mb` | `5000` | 本节 6.4 已设 |
| 框架层 | `application-prod.yml` `max-file-size` / `max-request-size` | `5000MB` | 见 7.3 |
| 网关层 | Nginx `client_max_body_size` | `5200m` | 略大于 5000，留 multipart 开销余量，见第 9 章 |

- `upload_base_path` 在后端启动时读取；如果后端已启动，修改后必须重启后端。

## 7. 阶段 6：后端部署

### 7.1 创建后端目录

```bash

```

### 7.2 生成 JWT secret

服务器执行：

```bash

```

复制输出备用，后续在 7.6 填入密钥文件 `intlmed.env` 的 `JWT_SECRET`。

### 7.3 生产配置文件（已在项目内，用环境变量注入密钥）

本项目采用「项目内配置文件 + 环境变量注入密钥」方案：

- 配置文件 `backend/src/main/resources/application-prod.yml` 已随项目提交，会被打进 JAR。
- 文件里所有敏感值都写成环境变量占位符（如 `${DB_PASSWORD}`、`${JWT_SECRET}`），**不含任何明文密码**，因此提交到 git 和打进 JAR 都安全。
- 真实密码在服务器上通过 systemd 的环境变量文件注入，见 7.6。

`application-prod.yml` 内容（已在项目中，无需在服务器手动创建）：

```yaml
server:
  port: 8080

spring:
  servlet:
    multipart:
      max-file-size: 5000MB
      max-request-size: 5000MB
  datasource:
    url: jdbc:mysql://localhost:3306/international_medical?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Hong_Kong&allowPublicKeyRetrieval=true&useSSL=false
    username: ${DB_USERNAME:intlmed}
    password: ${DB_PASSWORD}
    driver-class-name: com.mysql.cj.jdbc.Driver
  mail:
    host: ${MAIL_HOST}
    port: ${MAIL_PORT:587}
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
      database: 0
      timeout: 3000ms
      password: ${REDIS_PASSWORD}

mybatis-plus:
  mapper-locations: classpath*:mapper/**/*.xml
  type-aliases-package: com.intlmedical.entity
  configuration:
    map-underscore-to-camel-case: true

jwt:
  secret: ${JWT_SECRET}
  expiration: 86400000
  admin-expiration: 28800000

app:
  cors:
    allowed-origins:
      - https://www.scohospital.com
      - https://scohospital.com
      - https://admin.scohospital.com
  mail:
    from: ${MAIL_FROM:noreply@scohospital.com}
    verify-code-ttl: 600
    verify-code-resend-interval: 60
```

> 占位符语法说明：`${VAR}` 表示必须由环境变量提供；`${VAR:默认值}` 表示环境变量缺失时用默认值。所以 `DB_PASSWORD`、`REDIS_PASSWORD`、`JWT_SECRET`、`MAIL_*` 这些没默认值的，必须在服务器环境变量里提供，否则后端启动会报错——这正是我们要的：强制生产环境提供真实密钥。
>
> CORS 域名直接写死在文件里（非敏感，可提交）。如需改域名，改这个文件后重新打包即可。

### 7.6 创建密钥环境变量文件（服务器）

真实密码通过这个文件注入，不进 git、不进 JAR。先在服务器生成 JWT secret（若 7.2 已生成可复用）：

```bash
openssl rand -base64 48
```

创建密钥文件：

```bash
vi /opt/intlmed/config/intlmed.env
```

写入（把右侧换成真实值，等号两边不要加空格，值不要加引号）：

```env
DB_USERNAME=intlmed
DB_PASSWORD=换强密码_DB
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=换强密码_REDIS
JWT_SECRET=换成上面openssl生成的随机串
MAIL_HOST=smtp.你的邮件服务商.com
MAIL_PORT=587
MAIL_USERNAME=noreply@scohospital.com
MAIL_PASSWORD=换成邮箱授权码
MAIL_FROM=noreply@scohospital.com
```

收紧权限（只有 deploy 能读）：

```bash
chmod 600 /opt/intlmed/config/intlmed.env
chown deploy:deploy /opt/intlmed/config/intlmed.env
```

> 说明：这个文件是纯 `KEY=VALUE`（systemd EnvironmentFile 格式），不是 yaml。它绝不能提交到 git；`/opt/intlmed/config/` 目录也不在项目仓库里，天然隔离。

### 7.7 创建 systemd 服务

服务器新建：

```bash
vi /etc/systemd/system/intlmed-backend.service
```

写入：

```ini
[Unit]
Description=International Medical Backend
After=network.target mysqld.service redis.service

[Service]
User=deploy
WorkingDirectory=/opt/intlmed
EnvironmentFile=/opt/intlmed/config/intlmed.env
ExecStart=/usr/bin/java -Xms512m -Xmx2g \
  -Dspring.profiles.active=prod \
  -jar /opt/intlmed/app.jar
SuccessExitStatus=143
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

重点：

- `-Dspring.profiles.active=prod` 不能删，否则会退回源码默认配置（本地 MySQL 密码、默认 JWT secret、localhost CORS）。
- `EnvironmentFile=/opt/intlmed/config/intlmed.env` 不能删，否则 `${DB_PASSWORD}` 等占位符没有值，后端启动会因缺少密钥而报错。
- 因为 `application-prod.yml` 已打进 JAR，这里**不再需要** `-Dspring.config.additional-location`。

### 11.1 修改默认后台账号密码

## 14. 常见问题排查

| 现象 | 常见原因 | 处理方式 |
|---|---|---|
| 前端接口 CORS 报错 | 生产 CORS 未生效或仍是 localhost | 确认 systemd 有 `-Dspring.profiles.active=prod`；CORS 域名在 JAR 内 `application-prod.yml`，改后需重新打包并重启后端 |
| 后端启动报缺少环境变量 / 占位符无值 | `intlmed.env` 缺失或 systemd 没配 `EnvironmentFile` | 确认 `/opt/intlmed/config/intlmed.env` 存在且 service 文件有 `EnvironmentFile=` 那行 |
| 后端连不上数据库 | MySQL 账号、密码、库名错误 | 检查 `spring.datasource`，执行 `mysql -u intlmed -p international_medical` 验证 |
| Redis 验证码异常 | Redis 密码不一致或未启动 | 检查 `/etc/redis.conf` 的 `requirepass` 与 `intlmed.env` 的 `REDIS_PASSWORD` 是否一致，执行 `redis-cli -a 密码 ping` |
| 图片上传成功但打不开 | `upload_base_url` 仍是 localhost 或 `upload_base_path` 错 | 更新 `site_config`，重启后端 |
| 上传视频提示超过限制 | DB 中 `upload_max_size_mb` 没改或过小 | 改为 `5000` 后重启后端 |
| 上传大视频报 413 | Nginx `client_max_body_size` 太小 | 配置 `client_max_body_size 5200m`，执行 `nginx -t && systemctl reload nginx` |
| 大视频上传中途断开 | Nginx 反代超时 | 增大 `proxy_read_timeout` 和 `proxy_send_timeout` |
| 刷新前端路由 404 | 缺少 SPA fallback | Nginx `location /` 使用 `try_files $uri $uri/ /index.html;` |
| HTTPS 证书申请失败 | DNS 未生效或 80 端口不通 | 检查 `dig`、安全组、firewalld、Nginx 80 监听 |
| systemd 启动后仍读默认配置 | 启动参数缺失 | 确认服务文件包含 `-Dspring.profiles.active=prod` 和 `EnvironmentFile=/opt/intlmed/config/intlmed.env` |
| 后台打不开但 site-a 正常 | Nginx `server_name` 或 DNS 配错 | 检查 `admin.scohospital.com` A 记录和 Nginx admin server 块 |
